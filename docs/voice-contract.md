# Формат AI-прототипа для Егора

Статус: предложение для согласования. Модель Pydantic:
`backend/app/schemas/voice.py`; машинная JSON Schema: `voice-command.schema.json`.
Это результат извлечения данных, а не HTTP-endpoint для исполнения команд.
STT и LLM остаются задачами Егора.

```json
{
  "schema_version": 1,
  "intent": "create_task",
  "source_text": "Напомни завтра в десять погулять с Марсом",
  "pet_name": "Марс",
  "title": "Прогулка",
  "due_at": "2026-11-27T10:00:00+03:00",
  "recurrence": "none",
  "missing_fields": [],
  "requires_confirmation": true
}
```

Пример рассчитан для команды 26 ноября 2026 года в `Europe/Moscow`.
Вход извлечения всегда содержит текст, текущее время с offset и IANA timezone
пользователя. Нельзя рассчитывать «завтра» по часовому поясу сервера.

- `intent`: `create_task`, `log_care`, `unknown`.
- Неизвестные значения полей — `null`. `missing_fields`: `pet`, `title`, `due_at`,
  `intent`. Для записи уже выполненного ухода будущий срок не требуется.
- Если «вечером» не позволяет определить время, `due_at=null`, а `due_at`
  включается в `missing_fields`. Не подставлять случайное время.
- `recurrence`: `none`, `daily`, `weekly`, `monthly` либо `null`, если не удалось
  определить. Сложные повторы потребуют расширения контракта в третьем спринте.
- Имя питомца — подсказка, не подтверждённый UUID. Совпадающие имена требуют выбора;
  права на выбранного питомца проверяет backend при сохранении.
- `requires_confirmation` всегда `true`; лишние поля и время без offset отклоняются.
  Во втором спринте распознавание вообще не изменяет данные. С третьего — сохранение
  только через подтверждённую форму с полноценной серверной валидацией.
- Пароли, токены и ключи LLM не входят в этот JSON.

Егору нужно подтвердить имена полей, перечень намерений и набор примеров.
Кириллу — обработку пропущенных полей, выбор питомца и показ формы подтверждения.
