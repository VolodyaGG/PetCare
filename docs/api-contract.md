# API v1: предложение для согласования

Статус: подготовлено для Вовы; Кирилл и Егор ещё не подтвердили.
Реально реализован только `/health`. Перечень ниже задаёт будущие контракты,
а не обещает работающие endpoints следующих спринтов.

## Общие правила

- Бизнес-API: `/api/v1`. Инфраструктурная проверка: `/health`.
- JSON в UTF-8, поля `snake_case`, идентификаторы UUID в строках.
- Временные метки RFC 3339 с UTC-offset; сервер хранит `timestamptz` в UTC.
  Даты рождения — `YYYY-MM-DD` без времени. Клиент передаёт IANA timezone
  (например, `Europe/Moscow`) для повторов и интерпретации «завтра».
- Начиная со спринта 2: `Authorization: Bearer <access_token>`.
  Пользователь определяется из токена, не из переданного `user_id`.
- Создание — `201`, чтение/изменение — `200`, удаление — `204` без тела.
- Ошибки: `400` некорректное действие, `401` нет сессии, `403` запрет действия,
  `404` объект не найден или недоступен, `409` конфликт, `422` валидация.
- Единый ответ ошибки: `{"error":{"code":"...","message":"...","details":null}}`.
  Поле `details` необязательно. Валидация использует список с `location`, `message`, `type`.
  В ошибках нет паролей, токенов, SQL и строки подключения.
- Списки: `{"items": [...], "limit": 50, "offset": 0}`; параметры `limit=1..100`,
  `offset>=0`, стабильная сортировка по `created_at`, затем `id`.
- `PATCH`: отсутствующее поле не меняется; `null` очищает только nullable-поле.
- OpenAPI действующего сервера — источник реализованных HTTP-схем. Предложения
  следующих спринтов остаются здесь до реализации и согласования.

## Очередь endpoints

| Спринт | Метод и путь | Назначение |
| --- | --- | --- |
| 1 | `GET /health` | Реализовано: `200 {"status":"ok","database":"ok"}` либо `503` |
| 1, Артур | `GET /api/v1/demo/pets` | Только фиксированные вымышленные данные, без записей из БД |
| 2 | `POST /api/v1/auth/register` | Регистрация |
| 2 | `POST /api/v1/auth/login` | Вход |
| 2 | `POST /api/v1/auth/refresh` | Обновление сессии |
| 2 | `POST /api/v1/auth/logout` | Отзыв сессии |
| 2 | `GET, POST /api/v1/pets` | Список и создание |
| 2 | `GET, PATCH, DELETE /api/v1/pets/{id}` | Один питомец |
| 3 | `GET, POST /api/v1/tasks` | Задачи и фильтры |
| 3 | `PATCH, DELETE /api/v1/tasks/{id}` | Изменение задач |

Схемы авторизации, задач, повторов и загрузки фото уточняются перед соответствующим
спринтом. Несогласованные маршруты не добавлены как заглушки с фиктивным успехом.

## Клиент iOS

В симуляторе базовый адрес `http://127.0.0.1:8000`. На физическом iPhone `localhost`
означает сам телефон. Для проверки по LAN нужно отдельно настроить доступ к Mac
и разрешения iOS; текущий Compose слушает только loopback. Тестовый HTTPS-сервер
относится к следующему спринту и здесь не создаётся.

Предложенные лимиты: имя питомца 100 символов, заголовок задачи 120,
распознанная команда 4000. Они действуют в прототипном AI-контракте;
до реализации продуктовых форм Кирилл и Егор должны подтвердить их.

## Согласованный голосовой контракт v2

Форматы извлечения и ответа клиенту разделены; см. [голосовой контракт](voice-contract.md).
Ответ содержит несколько `drafts`, непонятые фрагменты, опору записи, две ревизии
(разбора и расшифровки), UTF-16-диапазоны события/действия/времени и отдельные
информационные пометки / блокирующие проблемы. Схема ответа — `voice-command.schema.json`,
схема вывода модели — `voice-extraction.schema.json`.

Будущий `POST /api/v1/voice/interpret` подключается в общий v1 router; endpoint пока
не реализован. Ключ повторов включает авторизованного пользователя, запись и ревизию;
конфликт содержимого — `409`, истечение 15-минутного хранения — явный `410` без
повторного вызова модели. Эти правила описаны для будущего обработчика, кеша пока нет.
